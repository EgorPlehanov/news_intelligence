Современное информационное общество сталкивается с огромным объемом новостных материалов, которые ежедневно публикуются в Интернете. Такой программный продукт обладает значительными преимуществами. Во-первых, он позволит пользователям быстро получать оперативную информацию о текущих событиях и тенденциях в различных областях, таких как политика, экономика, спорт, культура и т.д. Это особенно полезно для журналистов, аналитиков и всех, кто нуждается в актуальных новостях для принятия решений или создания информационных материалов.

Программа будет автоматически собирать новости из различных источников, группировать их по темам, сокращать полученные группы до нескольких ключевых предложений и передавать их в ChatGPT для генерации читабельного текста и заголовков. В результате, обработанные новости будут отображаться на моем веб-сайте. Таким образом, пользователи смогут сосредоточиться на анализе и интерпретации новостей, минуя необходимость в множественных запросах и поиске нужной информации.

### 1.2 Определение требований к разрабатываемому продукту

Ниже представлены основные требования к функциональности и возможностям программы, которая разрабатывается для сбора, анализа и предоставления сводки новостей:

- **Сбор и сохранение новостей**
  
  Программа должна иметь возможность собирать новости с различных новостных ресурсов и сохранять их в базу данных для последующего использования.

- **Запрос сводки новостей**
  
  Пользователь должен иметь возможность запрашивать сводку новостей из программы, указывая заданный день и выбранные источники новостей.

- **Кластеризация новостей**
  
  Программа должна проводить кластеризацию новостей, разбивая их на группы по темам. Кластеризация должна быть автоматизированной и основываться на схожести содержания новостей.

- **Создание краткой сводки**
  
  Для каждой группы новостей, программа должна генерировать краткую сводку, содержащую основные аспекты каждой темы. Сводка должна быть информативной и содержать ключевую информацию.

- **Выделение ключевых слов**
  
  Для каждого кластера новостей, программа должна определять и выделять ключевые слова, которые наиболее точно описывают содержание данного кластера. Это поможет пользователям быстро понять основные темы, представленные в сводке новостей.

- **Предоставление списка ссылок на источники новостей**
  
  Каждая новостная сводка, созданная программой, должна содержать список ссылок на источники, откуда были получены новости. Это позволит пользователям обратиться к оригинальным источникам для получения более подробной информации или прочтения полного текста новостей.

- **Вывод результатов**
  
  Итоговая сводка новостей, включающая краткие сводки по каждой группе новостей и выделенные ключевые слова, должна быть представлена на экране в приложении для пользователей.

#### 1.3.1 Сбор данных

В задачах сбора и обобщения новостей важным принципом является сбор актуальных и достоверных данных из различных источников. Это может включать парсинг веб-страниц, использование API или другие методы для получения информации.

Одним из ключевых методов для сбора информации с новостных ресурсов является парсинг. Для реализации парсинга в разработанной программе будут использоваться следующие методы:

1. **Парсинг HTML-страниц с использованием BeautifulSoup и requests**: этот метод позволяет собирать данные со страниц различной сложности, извлекать нужную информацию и сохранять ее в базу данных. BeautifulSoup обеспечивает удобный доступ к элементам HTML-структуры, а библиотека requests позволяет выполнять запросы к серверу и получать HTML-страницы новостных ресурсов.

   **Преимущества**:
   - гибкость и адаптивность: парсинг HTML-страниц позволяет собирать данные с различных источников без зависимости от наличия API;
   - доступность: технологии BeautifulSoup и requests широко распространены и хорошо поддерживаются сообществом разработчиков.

   **Недостатки**:
   - возможные изменения структуры страниц: при изменении HTML-структуры источников данных может потребоваться обновление парсера для корректного сбора информации;
   - ограничение доступа: некоторые новостные ресурсы могут применять меры защиты от парсинга, например, ограничивать количество запросов или вводить капчу.

2. **Использование Selenium для сбора данных с динамических страниц**: некоторые новостные ресурсы используют динамические страницы, которые требуют прокрутки или взаимодействия с элементами на странице для загрузки полной информации. В таких случаях Selenium обеспечивает автоматизацию браузера, позволяя собирать данные со сложных и интерактивных страниц.

   **Преимущества**:
   - работа с динамическими страницами: Selenium позволяет эмулировать взаимодействие пользователя с веб-страницей, позволяя собирать данные с динамически изменяемых и сложных страниц;
   - гибкость: С помощью Selenium можно реализовать различные сценарии сбора данных, такие как автоматическая прокрутка страниц, заполнение форм и другие взаимодействия с элементами на странице.

   **Недостатки**:
   - больший объем ресурсов: использование Selenium требует наличия и запуска полноценного браузера, что может потребовать больше ресурсов компьютера и увеличить время выполнения сбора данных;
   - большая сложность настройки: поскольку Selenium представляет собой инструмент автоматизации браузера, его настройка и использование может быть более сложным по сравнению с парсингом HTML-страниц.

Кроме выбранных методов, существует также использование API новостных источников. Однако, в данной работе не было выбрано использование API по следующим причинам:
- ограничения доступа: не все новостные ресурсы предоставляют API для сбора данных. Доступ к API может быть ограничен, требовать авторизации или платную подписку;
- ограниченный объем данных: некоторые API могут предоставлять ограниченный объем данных или ограничения по частоте запросов;
- зависимость от доступности API: в случае, если API новостного источника недоступно, невозможно будет собрать данные. Парсинг HTML-страниц позволяет обойти эту проблему, поскольку он не зависит от наличия API.

Таким образом, выбранные методы парсинга HTML-страниц и использование Selenium обладают гибкостью, позволяют собирать данные со страниц любой сложности и не требуют зависимости от доступности API.

#### 1.3.2 Предобработка текста

Предобработка текста играет важную роль в задаче кластеризации новостей. Этот этап позволяет привести тексты к единому формату, удалить шумовые и малозначимые элементы, а также извлечь ключевые признаки, необходимые для последующего группирования и классификации новостных статей. Для решения данной задачи были выбраны следующие технологии.

1. **NLTK (Natural Language Toolkit)** представляет собой библиотеку для обработки естественного языка, которая включает в себя различные инструменты и ресурсы для анализа и предобработки текста. В выбранной задаче NLTK использована для удаления стоп-слов и токенизации текста.

   **Преимущества**:
   - наличие набора стоп-слов: наличие готового набора стоп-слов на русском языке в NLTK позволяет удалять часто встречающиеся и малозначимые слова, что способствует более точному анализу и интерпретации содержания новостей;
   - токенизация текста: функция word_tokenize позволяет разделить текст на отдельные токены (слова), что является важным шагом для последующей обработки и анализа текста.

2. **Langdetect** является инструментом для определения языка текста на основе его содержимого. Основное его преимущество заключается в автоматическом определении языка, что позволяет без явного указания или предварительного знания источника обеспечить гибкость в работе с различными языками и источниками новостей. Недостатком является возможные ошибки определения языка. Несмотря на высокую точность определения языка, иногда может возникать некоторая погрешность, особенно при обработке текста с множеством языковых смешений.

3. **Pymorphy2** является библиотекой для лемматизации слов. Лемматизация позволяет привести слова к их базовой форме, что помогает в объединении и анализе текста. Основное из-за чего был выбран этот модуль — это лемматизация слов на русском языке.

Таким образом, выбранные методы и инструменты предобработки данных (NLTK, Langdetect и Pymorphy2) обладают необходимой функциональностью и гибкостью для обработки текста новостей. Они позволяют удалить стоп-слова, разделить текст на токены, определить язык текста и лемматизировать слова на различных языках.

#### 1.3.3 Кластеризация данных

Важным этапом в обработке и анализе новостей является задача кластеризации, которая позволяет группировать новости по сходству их содержания. Кластеризация позволяет образовать категории или тематические группы, упрощая навигацию и поиск в больших объемах информации. Ее целью является выявление скрытых структур и связей между новостными статьями, что позволяет пользователям быстро ориентироваться и сосредоточиться на интересующих их темах.

Для достижения этой цели, в рамках работы, для кластеризации новостей по темам был выбран метод HDBSCAN.

**Преимущества алгоритма HDBSCAN**:

- **Автоматическое определение числа кластеров**: HDBSCAN позволяет определить оптимальное количество кластеров на основе структуры данных. Это особенно полезно, когда число кластеров неизвестно заранее или может меняться со временем.

- **Обнаружение выбросов**: HDBSCAN способен выявить выбросы в данных, то есть объекты, которые не принадлежат ни одному кластеру. Это позволяет исключить нетипичные или шумовые новости, которые не относятся к основным темам.

- **Работа с неоднородными кластерами**: HDBSCAN способен обрабатывать кластеры различных размеров и плотностей. Он позволяет формировать кластеры разной формы и структуры, а также распознавать плотные и разреженные области данных.

- **Гибкость параметров**: HDBSCAN имеет несколько настраиваемых параметров, таких как минимальный размер кластера (min_cluster_size), которые позволяют регулировать процесс кластеризации под конкретную задачу.

- **Учет плотности**: HDBSCAN основан на плотностных кластеризационных методах, что позволяет учитывать плотность объектов в пространстве признаков. Это особенно полезно для обнаружения кластеров в данных с разной плотностью и шумами.

- **Высокая производительность**: HDBSCAN обладает хорошей производительностью и масштабируемостью даже для больших объемов данных. Это позволяет эффективно обрабатывать и кластеризовать большие наборы новостей.

Однако, важно также рассмотреть и другие варианты кластеризации новостей, такие как использование предобученных моделей или моделей, требующих обучения. Хотя эти методы могут предоставить более точные результаты, их применение может потребовать сбора большого объема данных и настройки модели, что может быть трудоемким процессом. Также существует риск проблем, таких как переобучение модели или ошибки кластеризации, которые могут быть сложными для исправления путем настройки параметров.

Поэтому, с учетом требований проекта, метод HDBSCAN был выбран в качестве оптимального варианта для кластеризации новостей по темам.

#### 1.3.4 Суммаризация данных

В рамках задачи суммаризации текста важным методом, который был выбран для применения, является LSA (Latent Semantic Analysis) — метод скрытого семантического анализа. Он позволяет выделить наиболее значимые предложения из текстов новостей, что является важным этапом перед передачей текстов языковой модели, такой как ChatGPT. Пропуск этого этапа может привести к ненужной расходу вычислительных ресурсов и финансовых затрат, особенно при обработке больших объемов текста.

Метод LSA имеет свои преимущества в задаче суммаризации текста. Он основывается на матричных операциях и статистическом анализе, что позволяет выявить семантические связи между словами и предложениями. Это позволяет определить наиболее информативные предложения, содержащие ключевую информацию, и использовать их для создания краткой сводки новости.

Хотя для задачи суммаризации также можно рассмотреть использование предобученных моделей, таких как BERT. Однако их использование может сопровождаться определенными проблемами. Во-первых, такие модели требуют значительных вычислительных ресурсов для обработки текста, особенно при работе с большими объемами данных. Кроме того, обучение и настройка предобученных моделей также могут быть трудоемкими. Для достижения хорошего качества работы модели может потребоваться большой объем данных и значительное время на обучение. При этом возникают проблемы, такие как переобучение, когда модель "запоминает" тренировочные данные и показывает плохую обобщающую способность на новых текстах, а также необходимость в тщательной настройке гиперпараметров модели для достижения оптимальных результатов.

Исходя из этих соображений, метод LSA был выбран в качестве подхода для суммаризации текста в данной работе, благодаря своей эффективности, относительной простоте и экономии ресурсов.

#### 1.3.6 Выделение ключевых слов

Выделение ключевых слов является важным аспектом для определения главной информации в тексте новостной сводки, аналогично заголовку новости. Ключевые слова представляют собой основные понятия, термины или фразы, которые наиболее точно отражают содержание и основные темы текста.

Путем выделения ключевых слов можно создать компактное и информативное представление новости, которое поможет читателю быстро понять основную суть и содержание текста. Это особенно важно в контексте новостных сводок, где требуется передать основные события и факты в краткой форме.

Выделение ключевых слов позволяет сфокусироваться на наиболее значимых аспектах новости и обеспечить их ясное и понятное представление. Эти ключевые слова могут быть использованы для формирования заголовков, подзаголовков или общего описания новости, что помогает читателю быстро ориентироваться и принять решение о дальнейшем чтении.

Для выделения ключевых слов в разработанной программе будет использовано Natural Language Processing (NLP) — область компьютерной лингвистики, которая занимается обработкой и анализом естественного языка. NLP позволяет автоматически распознавать, интерпретировать и генерировать текст на естественном языке.

#### 2.1.1 Архитектура

Приложение для сбора и обобщения новостей в сети Интернет разработано с использованием современных технологий и модульной архитектуры. В основе архитектуры лежит паттерн MVC (Model-View-Controller), который обеспечивает разделение логики приложения, представления данных и обработки запросов.

Компоненты структуры MVC необходимые для реализации проекта:

1. **Модель (Model)**
   - модель представляет собой набор классов, описывающих структуру и связи между данными;

2. **Представление (View)**

### 2.3 Модуль кластеризации новостей и выделения ключевых слов кластеров

Модуль кластеризации новостей предназначен для группировки новостных статей на основе их содержимого. Он использует методы обработки текста, векторизации и кластеризации для создания кластеров новостей с похожими темами.

**Алгоритм работы модуля**:

1. **Входные данные**
   - Список источников новостей.
   - Дата, на которую необходимо получить новости.

2. **Получение новостей**
   Используя CRUD-операцию, модуль получает новостные статьи из базы данных, соответствующие заданным источникам и дате.

3. **Подготовка данных**
   - извлечение текста из каждой новостной статьи;
   - применение предварительной обработки текста, включающей токенизацию, приведение к нижнему регистру, удаление стоп-слов, лемматизацию и удаление символов пунктуации.

4. **Векторизация данных**
   Используя TF-IDF (Term Frequency-Inverse Document Frequency), тексты новостей преобразуются в числовые векторы, отражающие их семантическую схожесть.

5. **Кластеризация новостей**
   - применяется алгоритм кластеризации HDBSCAN (Hierarchical Density-Based Spatial Clustering of Applications with Noise) для группировки новостей по сходству;
   - метод HDBSCAN позволяет автоматически определить количество кластеров и обнаружить выбросы (новости, не принадлежащие ни одному кластеру).

6. **Распределение новостей по кластерам**
   - каждой новости присваивается метка кластера;
   - новости с меткой -1 считаются выбросами и исключаются из кластеризации;
   - создаётся словарь, в котором каждому кластеру соответствует список новостей, принадлежащих этому кластеру.

7. **Извлечение ключевых слов**
   - для каждого кластера извлекаются ключевые слова на основе текстов новостей, принадлежащих кластеру;
   - извлечение ключевых слов осуществляется с помощью алгоритма подсчета встречаемости слов (CountVectorizer).

8. **Вывод результатов**
   Возвращается словарь, в котором каждому кластеру соответствует список новостей и список ключевых слов.

### 2.4 Модуль суммаризации новостных кластеров

Модуль суммаризации кластеров новостей имеет следующие основные принципы работы, использует определенные библиотеки и алгоритмы, а также выполняет определенный порядок действий.

**Основные принципы работы**:

1. **Кластеризация новостей**: сначала новости группируются в кластеры на основе их сходства. Это позволяет выделить связанные тематические группы новостей, которые можно далее суммаризовать отдельно.

2. **Сокращение текста**: для каждого кластера новостей применяется алгоритм суммаризации, который позволяет сжать содержание каждого кластера до более краткой формы. Это помогает представить основные и важные аспекты новостей без излишней детализации.

**Используемая библиотека**: **sumy** — это библиотека для автоматической суммаризации текста на основе различных алгоритмов. Она предоставляет удобные классы и методы для обработки и суммаризации текстов.

**Используемый алгоритм**: **LSA (Latent Semantic Analysis)** — это метод анализа семантического содержания текста. Он использует матричные вычисления и сингулярное разложение для определения наиболее репрезентативных фрагментов текста и их последующей суммаризации.

**Порядок действий**:

1. **Подготовка текста**: исходный текст, содержащий новости, подается на вход модулю суммаризации.

2. **Кластеризация новостей**: новости группируются в кластеры на основе их сходства. Это может включать использование алгоритмов кластеризации, таких как K-means или DBSCAN.

3. **Суммаризация кластеров**: для каждого кластера применяется алгоритм суммаризации. В вашем коде используется LSA, который принимает текст кластера в качестве входных данных и возвращает сжатую версию текста с указантым количеством предложений.

4. **Вывод результатов**: суммаризованные версии каждого кластера объединяются в один общий результат, который может быть представлен в виде строки выходных данных.

Код реализации суммаризатора приведен в репозитории на GitHub по следующему пути: `news_intelligence/app/news_processing/summarize/summarize_utils.py` в функции `summarize_text`, которая принимает текст и количество предложений для суммаризации и возвращает суммаризованную версию текста, используя LSA алгоритм из библиотеки sumy.

### 2.5 Модуль генерации текстов новостных сводок

Модуль предназначен для генерации текстов новостей и заголовков на основе суммаризированных кластеров новостей. Давайте рассмотрим общие принципы работы модуля, используемые библиотеки и алгоритмы.

Полный код модуля представлен в репозитории на GitHub по следующему пути: `news_intelligence/app/news_processing/summarize/summarize_clusters.py`.

**Принцип работы модуля**:

1. **Инициализация OpenAI API**: В начале модуля происходит инициализация API OpenAI с использованием ключа, который загружается из переменной окружения.

2. **Функция "get_response"**: Эта функция отправляет запрос к модели ChatGPT для получения ответа на основе сообщений.

3. **Функция "summarize_clusters"**: Основная функция модуля, которая принимает кластеры новостей в качестве входных данных.

**Для каждого кластера**:
- Собираются тексты новостей из кластера.
- Происходит сокращение текстов новостей с помощью функции "summarize_text" из модуля "summarize_utils".
- Формируются сообщения, содержащие системные и пользовательские роли, а также полученный сокращенный текст новостей. Эта часть связана с особенностями модели GPT-3.5 Turbo, которая используется в проекте. Данная модель изначально предназначена для работы в формате чата, поэтому запросы должны быть сформированы соответствующим образом, в виде переписки.
- Запрашивается заголовок для сокращенного текста с помощью функции "get_response".
- Запрашивается текст сводки новостей с помощью функции "get_response".
- Заголовок и текст сводки сохраняются в словаре для данного кластера.
- Суммируются использованные токены для каждого кластера, их количество возвращается в объекте ответа от модели. Данный шаг необходим для отслеживания затрат ресурсов на обработку запроса, так как при работе с API взымаются средства со счета аккаунта OpenAI.

4. **Функция "count_tokens"**: Эта функция считает количество токенов в тексте с использованием предварительно обученного токенизатора BERT. Используется для предварительной оценки стоимости запроса к OpenAI API.

5. **Модуль "summarize_utils"**: Этот модуль содержит вспомогательные функции для суммаризации текста и оценки качества сокращения.

**Используемые библиотеки**:

- **openai**: библиотека для работы с OpenAI API.
- **dotenv**: библиотека для загрузки переменных окружения.
- **transformers**: библиотека для использования предварительно обученных моделей NLP, включая токенизаторы.
- **sumy**: библиотека для автоматической суммаризации текста.
- **rouge_score**: библиотека для вычисления метрик ROUGE (Recall-Oriented Understudy for Gisting Evaluation).
- **sklearn**: библиотека для вычисления метрик кластеризации (Silhouette Score, Davies-Bouldin Index, Calinski-Harabasz Index).
- **nltk**: библиотека для обработки естественного языка, используемая для удаления стоп-слов и токенизации.

**Алгоритмы**:

- **Суммаризация текста**: используется алгоритм LSA (Latent Semantic Analysis) для автоматической суммаризации текста с помощью библиотеки sumy.
- **Оценка качества сокращения текста**: используются различные метрики, такие как коэффициент Жаккара, косинусное расстояние, BLEU (Bilingual Evaluation Understudy) и ROUGE F-мера. Эти метрики реализованы с помощью библиотек nltk и rouge_score.

**Общий порядок действий модуля "summarize_clusters"**:

1. Инициализация OpenAI API
2. Для каждого кластера новостей:
   - сбор текстов новостей из кластера;
   - сокращение текстов новостей;
   - запрос заголовка для сокращенного текста;
   - запрос текста сводки новостей;
   - сохранение заголовка и текста сводки;
   - суммирование использованных токенов;
3. Вывод общего количества потраченных токенов
4. Возврат словаря с кластерами, содержащего заголовки и тексты сводок для каждого кластера

#### 3.2.2 Оценка качества кластеризации

Проведена оценка метрик для задачи кластеризации на основе одного набора данных, состоящего из более чем 400 новостных статей. Цель анализа заключалась в определении сходства объектов внутри каждого кластера и их отличия от объектов в других кластерах. Для этого использовалась функция `evaluate_clustering`, рассчитывающая три популярные метрики: коэффициент силуэта, индекс Дэвиса-Болдина и индекс Калински-Харабаса. Анализ полученных оценок метрик позволил оценить качество разделения кластеров и степень их перекрытия. Ниже представлены подробные результаты оценки каждой метрики и их интерпретация.

Код, использованный для расчета метрик, размещен в репозитории на GitHub по следующему пути: `news_intelligence/app/news_processing/summarize/summarize_utils.py` функция `evaluate_clustering()`, принимающая два параметра: список меток кластеров для каждого объекта и список признаков для каждого объекта.

**Результаты оценки метрик кластеризации**:

1. **Silhouette Score (Коэффициент силуэта)**
   - **Значение**: 0.07320457821894541
   - **Интерпретация**: Коэффициент силуэта измеряет, насколько каждый объект внутри своего кластера похож на другие объекты внутри этого же кластера по сравнению с объектами из других кластеров. Значение коэффициента силуэта находится в диапазоне от -1 до 1, где ближе к 1 означает лучшую кластеризацию.
   - **Вывод**: Значение 0.0732 говорит о том, что кластеры имеют перекрывающиеся границы и не очень хорошо разделены. Низкое значение коэффициента силуэта может указывать на сложности в определении четких кластеров.

2. **Davies-Bouldin Index (Индекс Дэвиса-Болдина)**
   - **Значение**: 2.4686075659206717
   - **Интерпретация**: Индекс Дэвиса-Болдина вычисляет среднюю "схожесть" между каждым кластером и его наиболее похожим соседом по сравнению с размерами кластеров. Низкое значение индекса указывает на лучшую кластеризацию.
   - **Вывод**: Значение 2.4686 означает, что кластеры имеют некоторое перекрытие и не определены очень четко. Более высокие значения индекса Дэвиса-Болдина указывают на более разрозненные и перекрывающиеся кластеры.

3. **Calinski-Harabasz Index (Индекс Калински-Харабаса)**
   - **Значение**: 2.963808837709727
   - **Интерпретация**: Индекс Калински-Харабаса является отношением межкластерной дисперсии ко внутрикластерной дисперсии. Более высокое значение индекса указывает на лучшую кластеризацию.
   - **Вывод**: Значение 2.9638 говорит о том, что внутрикластерная дисперсия больше, чем межкластерная дисперсия, что указывает на неопределенность в определении кластеров. Более высокие значения индекса Калински-Харабаса указывают на лучшую разделимость кластеров.

Итак, на основе полученных оценок можно сделать вывод, что кластеризация набора данных является не совсем оптимальной. Кластеры имеют перекрывающиеся границы и не определены четко. Возможно, это связано с природой данных или с необходимостью выбора других параметров алгоритма кластеризации.

В заключение, несмотря на не самые высокие оценки метрик кластеризации, проведенный анализ позволяет сделать следующие выводы. Большинство кластеров, сформированных на основе данных, демонстрируют корректность их структуры, а также связанность между собой по общей теме.

Важно отметить, что оценки метрик кластеризации, хотя и являются объективным инструментом для измерения качества разделения кластеров, не всегда полностью отражают смысл и цель исследования. В данном случае, наблюдение о корректности формирования кластеров и их связи по общей теме играет важную роль, дополняя численные оценки метрик.

Таким образом, в настоящем анализе результатов можно сделать вывод, что, несмотря на некоторую неопределенность и перекрытие кластеров, данные обладают явной структурой, формируют достаточно корректные кластеры и связаны между собой общей темой. Также стоит заметить, что более точная настройка параметров может значительно улучшить результат.

#### 3.2.3 Оценка качества суммаризации

Проведена оценка метрик для одной новостной сводки, состоящей из 37 кластеров новостей, чтобы проанализировать качество суммаризации.

Код, использованный для расчета метрик, размещен в репозитории на GitHub по следующему пути: `news_intelligence/app/news_processing/summarize/summarize_utils.py` функция `evaluate_text_reduction()`, принимающая два текста: исходный и обработанный.

В коде функции рассчитываются метрики, представляющие собой стандартные инструменты оценки качества суммирования текста. В результате анализа получили следующие оценки метрик, которые позволили получить представление о точности и полноте сокращенного текста. Вот краткий обзор каждой из них:

**Результаты оценки метрик суммаризации**:

1. **Коэффициент Жаккара** измеряет сходство между двумя множествами. В контексте суммирования текста он может измерять, насколько велико пересечение слов между исходным и сокращенным текстами. Ваш коэффициент Жаккара равен 0.188, что означает, что около 18.8% слов совпадают между исходным и сокращенным текстами. Это невысокий показатель, указывающий на то, что сокращенный текст сильно отличается от исходного.

2. **Косинусное расстояние** измеряет косинус угла между двумя векторами. В контексте суммирования текста оно может измерять, насколько векторные представления исходного и сокращенного текстов схожи. Косинусное расстояние 0.604 указывает на умеренное сходство между исходным и сокращенным текстами.

3. **BLEU (Bilingual Evaluation Understudy)** измеряет качество машинного перевода. Эта метрика также может быть использована для оценки качества суммирования текста, поскольку она сравнивает предложения в сокращенном тексте с предложениями в исходном тексте. Ваш BLEU-рейтинг равен 0.031, что является довольно низким показателем, указывающим на значительные различия между исходным и сокращенным текстами.

4. **ROUGE (Recall-Oriented Understudy for Gisting Evaluation)** также используется для оценки качества суммирования текста. F-мера, которую вы представили, включает в себя оценку полноты (recall) и точности (precision). Ваша F-мера ROUGE составляет 0.12, что также является относительно низким показателем.

5. **Удельная частота уникальных слов** измеряет количество уникальных слов в тексте относительно общего числа слов. Ваши данные показывают, что сокращенный текст содержит большую удельную частоту уникальных слов (0.896) по сравнению с исходным текстом (0.559). Это может указывать на то, что суммирование удалось сохранить значительную часть информации, но также может говорить о том, что сокращенный текст может быть менее понятным или согласованным, поскольку он содержит более разнообразные слова.

В целом, на основании этих метрик можно сделать вывод, что данная функция не очень хорошо справляется с суммированием текстов. Возможно, стоит попробовать другую модель или метод суммирования или постараться лучше подобрать параметры.

Также важно отметить, что в данном случае производилось значительное сокращение текста. Это может быть одной из причин, по которой наблюдаются различия между исходным и сокращенным текстами, выраженные низкими значениями метрик. Однако если провести не численную оценку, а самому почитать текст новостей и сгенерированную сводку, то сходство оказывается довольно близким.

**Подробное описание функций**

1. **Сбор новостей с различных новостных ресурсов**:
   - Приложение автоматически собирает новости с различных источников.
   - Оно использует специальные парсеры для извлечения новостей с каждого ресурса.

2. **Объединение новостей по теме**:
   - После сбора новостей приложение анализирует их содержимое и определяет, какие новости относятся к одной и той же теме.
   - Новости, относящиеся к одной теме, объединяются в сводку новостей.

3. **Создание сжатых новостных сводок**:
   - Объединённые в группы новости проходят сжатие, которое определяет самую важную информацию в их текстах и оставляет только ее.
   - Последним этапом сжатые тексты проходят через обработку искусственным интеллектом, который делает из самой важной информации новостного кластера связный текст, который приятно читать, и генерирует для него заголовок.

**Рекомендации и советы**

1. **Периодически обновляйте страницу сводок новостей**:
   - Чтобы получать свежие новости, рекомендуется периодически обновлять страницу сводок новостей.
   - Нажмите на кнопку "Создать сводку" в вашем веб-браузере, чтобы получить последние новости по выбранным параметрам. Данное замечание относится к сводке за текущий день. Данные в базе обновляются каждый час.

2. **Настройте предпочтения новостей**:
   - Приложение может предоставить вам возможность выбрать источники новостей и даты, чтобы получать более релевантные сводки.
   - Рассмотрите возможность выбора интересующих вас источников новостей и дат в левой панели на экране приложения.

3. **Обращайтесь к источникам**:
   - При использовании приложения, важно понимать, что информация, предоставляемая в сводках новостей, проходит машинную обработку и объединение по теме. В результате этого процесса возможна некоторая путаница или потеря деталей изначальных новостей. Поэтому всегда рекомендуется обращаться к оригинальным источникам новостей для получения полной и точной информации.
   - Разработанный ресурс стремится предоставить вам новый опыт взаимодействия с новостной информацией, позволяя получать сводки новостей по различным темам в удобной форме. Однако гарантировать абсолютную точность и полноту сводок новостей невозможно, так как они являются результатом автоматической обработки.
   - Поэтому, если вам требуется более подробная или достоверная информация о конкретной новости, рекомендуется обратиться к оригинальному источнику новости — они приведены в каждой карточке и открываются по нажатию на кнопку «Показать источники». Проверка источников является важной практикой, которая поможет вам получить объективную и достоверную информацию, составить полную картину событий и принять осознанные решения на основе надежных источников.
